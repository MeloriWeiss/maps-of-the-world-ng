# Maps-of-the-World

## О продукте

**GameMaster Helper** — браузерная платформа для мастеров настольных ролевых игр и авторов игровых миров. Она объединяет редактор карт, библиотеку текстур и сообщество в одном приложении: пользователь может создать карту, сохранить её как черновик, опубликовать и получить обратную связь от других участников.

Основные возможности:

- создание и редактирование карт в мастерской с использованием текстур, объектов, текста и слоёв;
- сохранение черновиков и публикация готовых карт в общем каталоге;
- создание, наполнение и публикация наборов текстур;
- профили авторов, избранное, оценки и комментарии;
- форум для тематических обсуждений;
- административная панель с аналитикой посещений и регистраций, управлением пользователями, модерацией контента и журналом действий.

Публичные каталоги позволяют находить карты и наборы текстур сообщества, а личный профиль — управлять собственными материалами и сохранённым контентом. Редактор, профиль и административные разделы доступны только авторизованным пользователям с соответствующими правами.

Проект организован как Nx-монорепозиторий: клиентская часть написана на Angular, API — на NestJS, для доступа к PostgreSQL используется Prisma. В интерфейсе продукт называется **GameMaster Helper**, а историческое название репозитория — **Maps-of-the-World**.

## Запуск

### Подготовка

Для локальной разработки необходимы:

- Git;
- Node.js версии из файла `.nvmrc`;
- Corepack и Yarn;
- Docker Engine с Docker Compose.

Проверьте версии:

```bash
node --version
docker --version
docker compose version
```

Включите Yarn через Corepack и установите зависимости:

```bash
corepack enable
yarn install
```

Создайте в корне проекта файл `.env` как копию `.env.example`. Команда
копирования зависит от операционной системы, поэтому можно воспользоваться
файловым менеджером или средствами своей командной оболочки.

Корневой `.env` используется только при локальной разработке. В нём API
подключается к PostgreSQL и MinIO через опубликованные localhost-порты.
Значения по умолчанию подходят для локального запуска, но секреты можно
заменить своими.

Файл `.env` игнорируется Git. В репозиторий добавляется только шаблон
`.env.example`.

### Разработка

#### 1. Окружение

Запустите PostgreSQL, MinIO и pgAdmin:

```bash
yarn start:api-deps:docker
```

Команда остаётся активной и выводит общие логи контейнеров в терминал. Для
остановки всего development-окружения нажмите `Ctrl+C`.

После запуска доступны:

- PostgreSQL — `localhost:5433`;
- MinIO S3 API — `http://localhost:9000`;
- MinIO Console — `http://localhost:9001`.
- pgAdmin — `http://localhost:5050`.

Логин и пароль MinIO Console берутся из `MINIO_ROOT_USER` и
`MINIO_ROOT_PASSWORD` в корневом `.env`.

Бакет и отдельный пользователь приложения создаются автоматически.

Данные для входа в pgAdmin берутся из `PGADMIN_DEFAULT_EMAIL` и
`PGADMIN_DEFAULT_PASSWORD` в `.env`. При добавлении сервера PostgreSQL внутри
pgAdmin используйте имя хоста `db` и порт `5432`, потому что оба контейнера
находятся в одной Docker-сети.

#### 2. Подготовка базы данных

Для первой подготовки базы выполните:

```bash
yarn db:main:generate
yarn db:main:deploy
yarn db:main:seed
```

`db:main:deploy` создаёт схему из версионируемых миграций и поддерживает таблицу
`_prisma_migrations`. Используйте эту команду и для локальной разработки, и при
развёртывании готовых миграций.

`db:main:push` предназначен только для одноразовых экспериментов с отдельной пустой
временной базой. Не используйте созданную через `db push` базу для дальнейшей
разработки: у неё не будет истории миграций, и `migrate deploy` потребует baseline.

##### Суперадминистратор для разработки

Development seed создаёт аккаунт с ролью `SUPER_ADMIN`:

- email: `admin@example.com`;
- пароль: `Admin123`.

Команда `yarn db:main:seed` полностью очищает локальную main-базу перед
заполнением. Не запускайте её для production-базы. Полный список тестовых
аккаунтов и сценариев находится в
[`libs/api/database-main/src/lib/prisma/seed/README.md`](libs/api/database-main/src/lib/prisma/seed/README.md).

Чтобы создать суперадминистратора без очистки development-базы, задайте
`SUPER_ADMIN_EMAIL`, `SUPER_ADMIN_USERNAME` и `SUPER_ADMIN_PASSWORD` (не менее
12 символов), затем выполните:

```bash
yarn admin:create-super
```

Скрипт использует `MAIN_DATABASE_URL` из окружения и не создаёт второго
суперадминистратора, если такой пользователь уже существует. Инструкция для
production приведена в разделе «Создание production-суперадминистратора» файла
[DEPLOYMENT.md](DEPLOYMENT.md).

#### 3. Фронтенд

Откройте отдельный терминал и запустите фронтенд:

```bash
yarn start:web
```

#### 4. Бэкенд

Откройте ещё один терминал и запустите бэкенд:

```bash
yarn start:api
```

Перед запуском API команда автоматически применяет все ожидающие Prisma-миграции.
Если база недоступна или её схема не может быть обновлена, HTTP-сервер не запускается.

В итоге Docker обслуживает PostgreSQL, MinIO и pgAdmin, а фронтенд и API
работают локально с автоматической пересборкой при изменении исходного кода.
Фронтенд доступен по адресу `http://localhost:4200`, API — по адресу
`http://localhost:3000/api`.

Если окружение было запущено в фоне вручную или терминал завершился
некорректно, остановите контейнеры командой:

```bash
docker compose --env-file .env -f docker/docker-compose.dev.yml down
```

Данные PostgreSQL и MinIO сохраняются в Docker volumes и будут доступны при
следующем запуске. Не добавляйте флаг `--volumes`, если не хотите удалить
локальные данные.

Подробности об устройстве хранилища и резервном копировании находятся в
[`OBJECT_STORAGE.md`](OBJECT_STORAGE.md).

### Сборка

#### Фронтенд

Для сборки фронтенда:

```bash
yarn build:web:prod
```

#### Бэкенд

Для сборки бэкенда:

```bash
yarn build:api:prod
```

Развёртывание на сервере, включая выбор между собственным MinIO и Cloudflare
R2, настройку ENV, миграции, reverse proxy и резервное копирование, описано
отдельно в [DEPLOYMENT.md](DEPLOYMENT.md).

## Команды

### Из корня репозитория

| Команда                      | Описание                                                                                             |
| ---------------------------- | ---------------------------------------------------------------------------------------------------- |
| `yarn start:api`             | Запуск только бэкенда                                                                                |
| `yarn start:web`             | Запуск только фронтенда                                                                              |
| `yarn start:api-deps:docker` | Запуск приложений, необходимых для работы бэкенда, в Docker                                          |
| `yarn build:api:prod`        | Сборка бэкенда `для сервера`                                                                         |
| `yarn build:web:prod`        | Сборка фронтенда `для сервера`                                                                       |
| `yarn db:main:migrate`       | Применить миграцию к main базе данных                                                                |
| `yarn db:main:deploy`        | Применить готовые Prisma-миграции без создания новых                                                 |
| `yarn db:main:generate`      | Сгенерировать типы на основе схемы для main базы данных                                              |
| `yarn db:main:seed`          | Выполнить сидинг базы данных (заполнить тестовыми данными)                                           |
| `yarn admin:create-super`    | Создать единственного суперадминистратора из переменных окружения без очистки базы                   |
| `yarn db:main:push`          | Синхронизировать отдельную временную базу без истории миграций; не использовать в обычной разработке |
| `yarn lint`                  | Запустить линтер по всему монорепозиторию                                                            |
| `yarn test`                  | Запустить тесты по всему монорепозиторию                                                             |
| `yarn docs:gen`              | Сгенерировать документацию ко всему монорепозиторию                                                  |
| `yarn docs:watch`            | Запустить сервер для просмотра документации                                                          |

Примеры коммитов:

```bash

fix(backend): исправить обработку ошибок

```
