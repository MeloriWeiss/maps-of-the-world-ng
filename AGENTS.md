# AGENTS.md

## Общие правила

- Общайся с пользователем на русском языке.
- Не изменяй код, который не относится к текущей задаче.
- Сохраняй обратную совместимость, если явно не сказано обратное.
- Не добавляй зависимости без необходимости.
- Не запускай destructive-команды и не удаляй данные без подтверждения.

## TypeScript

- Используй строгую типизацию.
- Не используй `any`.
- Не применяй type assertions без необходимости.
- Предпочитай ранние возвраты глубокой вложенности.
- Публичные методы должны иметь понятные названия.
- Повторяющуюся логику выноси в отдельные функции или сервисы.
- Приватные переменные создавай с помощью нативного синтаксиса `#`, а не через ключевое слово `private`

## Angular

- Используй standalone-компоненты.
- Используй `ChangeDetectionStrategy.OnPush`.
- Для локального состояния предпочитай signals.
- Для потоков событий и HTTP используй RxJS.
- Не выполняй бизнес-логику в компонентах.
- Не обращайся к DOM напрямую, если задачу можно решить средствами Angular.
- Подписки должны корректно уничтожаться.
- Соблюдай существующее разделение feature/data-access/ui.
- Не вызывай функции и сложные геттеры в шаблоне, а по возможности полностью откажись от этого.

## NestJS

- Контроллеры должны заниматься только HTTP-слоем.
- Бизнес-логику размещай в сервисах.
- Проверяй входные данные через DTO и `class-validator`.
- Не возвращай внутренние ошибки и stack trace клиенту.
- Проверяй права доступа к изменяемым сущностям.
- Новые endpoint’ы документируй через Swagger.

## База данных

- Изменения Prisma schema сопровождай миграцией.
- Миграции не должны удалять пользовательские данные без подтверждения.
- Не используй `db push` вместо миграций для production-схемы.
- Не храни изображения и текстуры непосредственно в PostgreSQL.
- Для тяжёлых пространственных данных используй чанки.

## Рефакторинг

- Сначала зафиксируй существующее поведение.
- Не смешивай большой рефакторинг с новой функциональностью.
- При изменении публичного интерфейса обновляй всех потребителей.
- Удаляй устаревший код только после проверки использования.
- Сохраняй формат существующих данных или добавляй миграцию версии.
- После рефакторинга запускай сборку, lint и релевантные тесты.

## Проверка результата

Перед завершением задачи:

1. Запусти сборку изменённого приложения.
2. Запусти lint изменённых проектов.
3. Запусти релевантные тесты.
4. Выполни `git diff --check`.
5. Проверь основной пользовательский сценарий.
6. Сообщи, какие проверки прошли и какие не удалось выполнить.
