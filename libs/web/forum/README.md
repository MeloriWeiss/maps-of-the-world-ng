# Форум GameMaster Helper

Форум работает через HTTP. WebSocket, периодического опроса и дополнительных зависимостей нет.

## Возможности

- Разделы, поиск по названию/тексту/автору, активные и новые темы, темы без ответов, собственные темы.
- Создание и редактирование темы: локальный черновик отдельно для каждого аккаунта и темы, предпросмотр, подтверждение ухода.
- Постраничные комментарии, ответы на конкретное сообщение, постоянные ссылки, редактирование своего текста.
- Ошибки отправки не очищают текст; повторная отправка блокируется до завершения запроса.
- Администраторы закрепляют и закрывают темы, скрывают/восстанавливают сообщения. Ответы на скрытое сообщение сохраняются; скрытый текст не выдаётся публично.
- Действия модератора фиксируются в существующем журнале администрации.
- Закрытые темы нельзя редактировать или комментировать, включая прямые запросы к API.

## Архитектура

Состояние сценариев находится в ForumListStore, ForumThreadStore и ForumEditorStore библиотеки web-data-access. ForumService инкапсулирует HTTP-контракты. Компоненты отвечают за формы и навигацию.

На сервере ForumService проверяет авторство и состояние темы; роли модератора проверяют JwtAccessGuard и RolesGuard. При публикации и редактировании строка темы блокируется в транзакции, чтобы закрытие темы не могло пересечься с записью ответа. lastActivityAt меняется при новом ответе, но не при лайках и модерации.

Старые адреса /forum/:id и API сохранены. Старый GET деталей по умолчанию возвращает дерево комментариев; новый интерфейс использует includeComments=false и GET /forum-discussions/:id/comments. В пагинации учитываются и скрытые сообщения-заглушки, поэтому ссылки и цепочки остаются стабильными.

Интерфейс запрашивает `view=tree`: без `parentId` API возвращает корневые комментарии, с ним — страницу непосредственных ответов. `commentId` возвращает страницу корня и путь предков для раскрытия прямой ссылки. Без `view=tree` сохранена прежняя плоская пагинация. `ForumCommentTree` хранит раскрытые ветки и их страницы; глубина связей не ограничена, визуальный отступ ограничен тремя уровнями. Форма ответа располагается под выбранным сообщением. Изменение не требует новой миграции.

## Миграция

Перед запуском обновлённого API выполните:

```sh
yarn db:main:deploy
```

Миграция 20260913120000_expand_forum добавляет поля и недостающие разделы, не удаляет данные и не меняет существующие категории. Seed для обновления форума запускать не нужно: он очищает базу.

## SEO

Форум остаётся частью Angular SPA, без SSR и серверной HTML-версии. Изменения Nginx не требуются.

Главная форума, /forum/sections/:slug и /forum/:id имеют клиентские метаданные и canonical. Поиск, сортировки, дополнительные страницы, ссылки на комментарии, личная выборка и редакторы имеют noindex. В теме используется DiscussionForumPosting JSON-LD.

Для всего сайта сохранён единый статический public/sitemap.xml: в него добавлены публичные разделы форума. Отдельного sitemap и API для него нет. Новые темы доступны по обычным ссылкам из списка обсуждений; автоматическое включение динамических страниц в общий sitemap пока не реализовано.

## Проверки

```sh
yarn nx test api-forum --runInBand
yarn nx test web-data-access --runInBand
yarn nx test web-shared --runInBand
```

Дополнительный тест на настоящей локальной PostgreSQL:

```powershell
$env:FORUM_DATABASE_TESTS='1'
yarn nx test api-forum --runInBand --skipNxCache
```

Он поднимает временный HTTP-сервер, подставляет тестовые идентичности вместо JWT, проверяет реальные guards ролей, контроллеры, DTO и SQL-операции. Все созданные записи откатываются транзакцией, включая записи журнала. Существующие пользовательские данные не меняются. Это проверка форума, не повторный тест механизма выдачи JWT.
